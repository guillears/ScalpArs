- **Per-pair concentration check before any dimensional filter.** If ≥60% of a loser zone's loss is 1–2 pairs → ship a pair blacklist, not a dimension filter.
- **Caps for losers, multipliers for winners — never cross them.** Loser/Pattern-C cohort → tighter TP/SL caps. Winner/Pattern-W cohort → size multiplier. Multiplying a loser amplifies the loss; capping a winner chops the runner.
- **Pattern code = signature; treatment = empirical behavior.** A C-tagged cell can carry a multiplier if it wins cross-batch (e.g. C1 SHORT); a W-tagged cell can carry fixed exits if it loses.
- **"High WR but net-losing" is NOT a filter candidate *when the loss is sizing*.** A 60–75% WR cohort can be net-negative purely from a few multiplier-amplified fat-tail losers → fix sizing on the specific losers; don't block the winning cohort. Always de-multiply to 1× before judging; only a cohort still below the sleeve's breakeven WR with negative 1× expectancy (the expectancy bar below) is a filter candidate.
- **Non-monotonic single-variable pattern = confound** (don't filter a mid-range hole when both flanks win). **Small N (<10/bucket) = noise.**

## 🔴 Live-mode lessons (go-live 2026-11-14 → 11-16: −24 % in 36 h; rationale DECISION_LOG 551–563)
- **Paper ≠ live costs — every exit / entry counterfactual adds them:** market-close slippage (median ≈ 0.02 %, thin-coin outliers 0.3–0.6 % — INIT 0.37 % / $68), taker vs maker fee (≈ 0.03 %), and FUNDING (`funding_fee_usd`; squeezed coins switch to HOURLY funding at 0.2 %/h — INIT paid $33 in 96 s). A trail / stop exit is a market order after the turn; a resting maker TP pays 0. Never compare a trail and a fixed TP without these.
- **Every bot entry passes the order-book depth guard on BOTH sides** (the exit side can be the thin one) — momentum and flips ran unchecked for 2 days (DL 551 covered Frenzy / SURGE / Flatbase only). A sizing / execution guard missing on a sleeve is a BUG, not an observe item.
- **Size by edge AND clustering, before go-live:** momentum tickets at 3.5–4.4 × the account opened 3 at a time → one market move = −10–12 % (beyond the master's worst −11.6 % drawdown). Per-stop cost × the realistic same-window count must be shown for every sleeve; unproven-live sleeves start small (momentum 10×, DL 562) and grow on live evidence.
- **Read a live loss by cause before reacting:** $ by sleeve × {entry never worked · exit gave back · size · slippage · funding}; one market moment = ONE observation (3 fills in 60 s = 1 window).
- **Entry rules behave opposite across the BTC daily regime** (1 d EMA50 vs EMA200): a quality-score cut that won in Jun–Aug (BTC down) lost in Sep–Nov (BTC up). Test every entry separator × BTC daily trend at sign granularity; arm only with same-minute proof (same window, different score, different result) and ≥ 3 / 3 backtest seeds — else observe.
- **Never refit a rule around the trades that broke it** (rule B, DL 561: a cut built to spare 3 October winners is in-sample by construction) — track the refit as an observe line.
- **Every armed declared override carries a priced tight revert** — if the scout has no pricer for that sleeve (momentum shorts), say so and read it by hand at each batch review.
- **🔒 CAPACITY at every batch review (Nov-18, operator; DL 583 / 584):** every guarded fill carries the capacity stamps (`entry_cap_planned_usd` · `entry_cap_entry_side_usd` / `_exit_side_usd` · `entry_cap_binding_side` · `entry_cap_final_usd` · `entry_cap_frac` · `entry_depth_walk_pct` · `entry_depth_mode` · `entry_book_usd_02/_05/_1` · `entry_book_exit_usd_02/_05/_1`; the EXHAUSTION / Flatbase journals carry `cap_*` (FULL / SHRINK / SKIP / NOFILL) on every guarded OPENED / REFUSED row; `entry_book_bands_levels` says which read the bands came from). ## How to evaluate a proposed change
1. Build/refresh the dedup pool. 2. Re-simulate under the CURRENT exit/filter stack. 3. Report N · WR · **Avg P&L %** · Total$ (de-multiplied to 1×) · **daily compound return BEFORE → AFTER** (per sleeve, master per batch AND current batch, both on today's stack + sizing: DCR-cal = (Π_d (1 + r_d))^(1/D) − 1 over EVERY calendar day D of the batch, r_d = Σ the sleeve's fill % × today's intended size X ÷ 100 over the fills closed that day (ONE size, DL 503), 0 % on no-fill days; the account-path DCR (realised $ ÷ start-of-day equity, flows split) shown beside as "as traded" — NOT the dashboard %/day; operator 10-27 / 11-08) · per-pair concentration · multi-date consistency. 4. Counterfactual Δ with in-sample haircut. 5. Lock a pre-committed revert gate.
